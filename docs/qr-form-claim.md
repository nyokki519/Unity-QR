# Google申込情報からLINEの個別QRを受け取る

## 方式

Unity_Sの公開イベント申込 → 完了画面の「LINEで参加QRを受け取る」 → 申込専用コード入りのDMを本人が送信 → Googleが受理した名前・公開イベントID・日付で個別QRを返します。

Unity計測IDは匿名計測用のまま変更しません。ブラウザは申込ごとに32バイトのコードを作り、GoogleにはSHA-256ハッシュだけを送ります。原文コードは本人のLINEメッセージだけで扱い、QR DBにもハッシュだけ保存します。名前で既存参加者やイベントを照合しません。

Googleへのno-cors送信成功は申込受理を意味しません。既存Google FormのonSubmitトリガーから、別の共有認証キーでQRへ受理通知を送ります。Analyticsの参加予定者タブと同じ回答を正とするため、Analyticsの匿名参加者APIを本人確認に流用せず、PV・CVR・既存計測トリガーを変更しません。

## 導入手順

1. MacのUnity-QR-testで `feature/form-registration-claim` を取得・切り替え、`npm ci`。既存のデプロイ設定・DB・署名鍵を削除しない。
2. 既存Cloudflare公開トークンを非表示で設定し、`npm run cloud:update`。バックアップ取得・空DBへの復元検証に成功してから、既存Workerを更新します。
3. `npm run cloud:form-setup`。Macの暗号学的乱数で別のフォーム連携キーを作り、privateな `data/form-secret.key` とCloudflare secretへ保存し、クリップボードへコピーします。鍵はコンソールに表示しません。LINE/Growthの秘密鍵を流用しません。繰り返し実行では同じprivateファイルの鍵を再利用します。
4. Unity_SのPRのレビュー・公開を行います。QR設定が未接続なら既存のLINE案内へ戻るので、先に公開しても申込の保存処理を維持します。
5. **既存Googleフォーム** → Apps Script。Unity_Sの `integrations/google-form/RegistrationQr.gs` を追加し、プロジェクト設定のScript Propertiesへ **QR_FORM_SECRET** としてクリップボードの鍵を貼り付けます。秘密をチャットやソースに貼らない。
6. `setupUnityRegistrationQr` を実行し、Googleの権限を許可します。既存項目名・型の衝突を確認してから、任意の照合項目と専用トリガーを追加します。実際のentry値をprefillから取得し、QRの設定へ登録します。entry値を推測したり、ユーザーが手で設定ファイルへ写す必要はありません。
7. 自分の専用テスト申込でLINEリンクを開き、入力済みDMを送信します。リンクを開くだけでは送信されません。
8. 受付イベントのID連携が未設定なら、QR管理画面 → 設定 → 申込フォーム・QR受取 → 紐付け待ちから、**同じ日付の正しいQRイベント**を選びます。Analyticsから既に取り込んだ同一ID・日付のイベントなら自動照合されます。会場や受付時間を推測して新イベントを作りません。
9. 本人が同じDMを送り直し、名前・イベント・QR受付と二重受付を確認します。実参加人数を汚染しないテストイベントを使います。

本番Formの既存必須項目は `お名前`・`イベント名`・`日時`・`公開イベントID`。自由入力やID保存のない旧申込は従来のLINE受付を維持します。今回の専用コード導入より前の申込に、生コードを遡って生成・配布はしません。

## 保護・運用

- 受理通知の重複は回答IDのハッシュで拒否／同一内容なら回復。内容が変わる再利用は409で停止。
- 1コードは1LINEユーザーへ固定。他のLINEによる利用は拒否。
- 初めて紐づく参加者にはGoogleの申込名を利用。既存LINE参加者はスタッフ修正を保護して既存の名前を維持します。異なる申込名は自動上書きしません。
- 日付・定員・取消・受付終了はサーバーで検証。申込の名前を知っているだけではQRを取得できません。
- 専用ページは既存の短期署名QRを当日の受付時間だけ表示。共有リンクや転送で本人保証できるとは扱いません。
- DB Schema 4は追加のみ。Form設定・イベントID対応・受理レコード・LINE所有者をバックアップに含めます。生コード・shared secret・LINE secretは含めません。Schema 2/3 JSONを新コードの空DBへ復元できます。旧コードへの単純なロールバックはできません。
- 管理画面でQR受取導線を停止できます。新しいForm通知は拒否し、既存受付・保存済み申込・受取済みQRは維持します。Googleの専用トリガーを止める場合も、Growthトリガーや既存回答を削除しない。
- 受理通知が届く前は「未確認」、ID対応がない場合は「受付準備中」を返す。QRを発行して成功と偽りません。
- Apps Scriptの一時的な失敗は同一内容で3回再試行。以後の永続再処理は自動化していません。実行履歴で確認し、運営が対象回答を再処理します。名前・回答本文・秘密をログへ出さない。
- ページを閉じると未送信の生コードは失われます。申込を繰り返して重複回答を作らず、運営確認・手動受付で復旧します。iPhoneでLINEへの切替時に入力済みメッセージが残ることを実機確認してください。

本番のGoogle設定・実フォーム回答・LINE実送信・クラウド更新はこの開発環境では行っていません。テストとGitHub反映だけで本番接続済みとは扱いません。
