# 無料クラウド版 — Macを閉じても受付する

Cloudflare **Workers Free + SQLite Durable Object** に受付アプリとDBを置きます。
Macは公開・更新するときに使い、公開後の受付には不要です。無料の
`workers.dev` HTTPS URLを使い、ドメイン購入やRenderの有料サービスは不要です。

## 今回のMacから移行する

移行中は、以前の `trycloudflare.com` URLで新しい参加登録・受付を行わないでください。
アプリを動かしているターミナルで `Control+C` を押すと止められます。
元のDBとバックアップは残します。移行後はクラウド側だけで受付してください。

Macのターミナルで次を実行します。

```bash
cd "$HOME/Unity-QR-test" &&
git pull --ff-only &&
npm ci &&
npm run cloud:deploy
```

初回はブラウザでCloudflareへログインし、Wranglerのアクセスを許可します。
複数アカウントがある場合だけ、公開先の番号を選んでください。
`workers.dev`を初めて使うアカウントでは、Wranglerの無料サブドメイン作成案内に
従ってください。有料プランへの変更や支払い情報登録は行いません。

自動処理の内容:

1. Macの既存DBを読み取り専用で開き、オンラインバックアップを取得。
2. 既存の管理者・スタッフ・イベント・参加者・受付履歴・監査・同期待ちを保存。
3. Cloudflareの契約情報を読み、Workers Freeと確認できる場合だけ続行。
4. 新しい固有名のWorkerと無料プラン対応のSQLite Durable Objectを作成。
5. Macで使ったQR署名キーを秘密変数として設定。キーは表示・コミットしません。
6. 空のクラウドDBへ一度だけ移行し、応答の指紋と全テーブル件数を照合。
7. 一時的な移行用秘密変数を削除し、起動確認後に `/ops/` のURLを表示。

再実行時にはCloudflare上の公開先の所有マーカーも照合します。同名の別サービスや
所有を確認できないサービスは上書きしません。

**管理者のログイン名・パスワードはMacと同じです。** セッションは移さないため、
新しいURLでログインし直します。参加者・イベントID、来場日時、取消履歴と
QR署名キーは引き継ぎます。元のQR有効期限や受付時間帯は延長しません。

元DBが複数あるときは自動選択せず、`QR_DB_PATH` の指定を求めます。
この会話のMac設定は次です。

```bash
export QR_DB_PATH="$PWD/data/iphone-test.sqlite"
npm run cloud:deploy
```

秘密キーを作ったファイル `data/iphone-test-signing.key` と既存DBが必要です。
不足時には公開を止めます。空の新しいDBや架空の管理者を作って代用しません。

## 無料枠と反映間隔

2026-10-12に確認した公式仕様では、Workers Freeのリクエストは1日100,000件、
SQLite Durable Objectの保存容量はアカウント全体で5GBです。DOにもリクエスト・
処理時間・SQL行読書きの無料上限があり、他のアプリの使用量も含まれます。
上限を超えるとその操作が失敗します。Freeプランのままなら自動の超過課金は
ありませんが、無制限や稼働保証のあるサービスではありません。

公開ヘルパーは有料・判定できないWorkers契約や契約APIへのアクセス失敗で中止し、
プランを変更しません。契約APIの閲覧権限が必要です。Cloudflare側の契約を
手動で有料へ変えないでください。Renderの `render.yaml` は有料の別案なので使いません。

クラウド版は他端末の変更を約30秒ごと（現在の8秒タイマーにより最大約32秒間隔）に
再読込します。自分が行った受付・登録の結果は直後に反映します。受付はネット接続と
サーバーからの成功応答が必要です。無料枠超過・通信失敗を受付成功として表示しません。

公式資料:

- https://developers.cloudflare.com/workers/platform/pricing/
- https://developers.cloudflare.com/durable-objects/platform/pricing/
- https://developers.cloudflare.com/durable-objects/platform/limits/

## バックアップ・復旧

公開前のバックアップと状態ファイルはMacの `data/cloud-migration/` に保存します。
個人情報とパスワードハッシュを含むため、GitHubや共有チャットには送らないでください。
同じMacでの再実行は同じ公開先を使います。移行完了後は古いMacのデータを
再取込してクラウドの新しい履歴を上書きすることはありません。

公開コマンドを強制終了した際などに状態ファイルが破損すると、自動再実行が止まる
場合があります。状態ファイルを削除してやり直さず、元DB・バックアップ・クラウド
の公開先を保持して手動復旧してください。状態ファイルは秘密情報を含みます。

クラウドの最新バックアップは、管理者でログイン後、実際の公開URLの
`/api/v2/backup` を開いてJSONを保存します。Adminだけが取得でき、応答は
`no-store`です。QR署名キーとセッションはバックアップに含めません。
秘密キーは別途安全に保管してください。

復旧は既存DBを消さず、別の空のクラウドDBへバックアップを移して確認する方式です。
自動移行はJSON最大5MiB・全テーブル合計50,000行までです。これを超えると
データを削らず止めます。大きなDBの復旧は別途手順が必要です。

公開後、iPhoneで新URLへログインし、テストイベント・QR受付・二重受付・取消を
確認してください。Macを閉じても開けることも確認します。
この開発環境から利用者のCloudflareアカウントへ公開した事実はまだありません。
