# 既存operatorだけのパスワード再設定

利用者が2026-10-24 JSTに再設定を明示承認。読み取り診断で既存operatorが有効なAdmin・正常scrypt形式と確認済みで、バックアップ全行の復元も検証済み。

一時配信の再設定処理は、10分の期限と所有者用64桁hex Secret、同一OriginのPOST、デプロイ側Secretの固定計画がすべて揃う場合だけ動く。リクエストからユーザーやパスワードハッシュを指定できない。通常のログイン認証には流用できない。

既存DBの所有マーカーとoperatorの一意性・ID・enabled・Admin・事前ハッシュを確認し、1トランザクションでpassword_hash1件と当該ユーザーのsession失効だけを実行する。変更件数1以外やsession処理失敗はrollback。処理済みハッシュなら再実行で新しいsessionを失効させない。ユーザーの追加、DB初期化、他ユーザーや参加者・イベント・受付履歴の更新はしない。通常のStore初期化より前に処理する。

実行前に再取得したバックアップを600権限で保管し、別DBへ復元検証する。新パスワードはOS乱数で生成し、600権限のGit管理外ファイルにだけ保存する。チャット、ログ、コマンド引数に値を出さない。新ハッシュと期待する旧ハッシュは一時Secret内だけで使う。

適用後はバックアップの全行を比較し、operatorのハッシュ以外の全エクスポート対象行が同一であることを確認する。元モジュールとbindingsへ復元し、再設定計画・所有者キー・期限を削除する。元の本番コードで新パスワードのログイン・Admin session・バックアップ閲覧を確認し、検証用sessionをlogoutする。

ローカル検証: 全149件（113単体＋12 workerd＋15既存ブラウザ＋8運営ブラウザ＋1 LINEブラウザ）・型検査成功。実workerdで変更範囲、他Admin session保持、処理後の永続性、旧パスワード拒否、再実行時の新session保持を確認。独立レビューにCritical/Important指摘なし。本番の実行結果は別途記録し、テスト成功だけで復旧と報告しない。

## 本番適用結果（2026-10-24 JST）

承認に基づく再設定を完了。直前バックアップの復元検証→期待する既存operatorの状態確認→hash1件更新・当該session失効→全エクスポート行の比較が成功した。operatorのhash以外の行は一致。元モジュール・bindingsへ復帰し、一時Secretを削除した後、元コードで新パスワードのログイン・Admin session取得・検証sessionのlogoutまで成功。本番公開APIで一時診断の世代ヘッダーがない401応答へ戻ったことも確認した。新パスワードは非公開600ファイルにだけ保存し、この文書・Git・ログには記録していない。以前の入力との食い違いが発生した時期・原因までは断定しない。

配信APIの更新とDO実行世代は同じ確認ではない。CLI既定のDO更新戦略はdeferred/max_delay=300であり、復旧用配信では即時切替・一意な要求識別子・応答の世代確認を使った。実要求が期待世代でない場合はDBへ書き込まず中止し、復元・一時キー削除を行った。通常のGET /backupは監査行を追加するため、変更範囲の厳密比較にはSELECT専用スナップショットを使い、復元後の通常認証確認はlogin/session/logoutに限定した。
