# Studio転送機能の本番追加（OFF）

2026-10-24 JST。利用者の「OFFのまま」の説明確認後の「一旦それでいいかGO」に基づき、cbf9d04の転送機能を既存Workerへ追加した。公開版は3a2c876f-720f-4588-8cde-b7223a2d2408。mainや古い転送ブランチによる上書きはしていない。

- STUDIO_RELAY_ENABLED=false、STUDIO_ALLOWED_GROUP_IDSは空。転送待ちは0件。
- Worker名・DO namespace/class・既存vars/Secrets・公開JS/CSSを維持。既存Webhook URLもそのまま。
- 取得した最新バックアップと追加後バックアップを、別のメモリDBへ復元検証。portable受付データだけでなく、既存session・ログイン試行制限・適用済みreset marker・所有者metadataも含めた。
- 全エクスポート対象行・既存の運用テーブル行が追加前後で一致。ユーザー・パスワードハッシュ・参加者・イベント・受付履歴・sessionは変更していない。追加は空の転送テーブルとインデックスのみ。
- バックアップは実行環境の非公開領域へ権限600で保存。本文・パスワードハッシュ・認証値をログ/チャット/Gitへ出していない。

パスワードの提供・推測・再設定は行わず、期限付き所有者キーの読み取り専用経路で取得した。取得前の一時版はDB初期化/リセットを行わず、通常の認証済み閲覧でも既存processing行を変更しない。バックアップ取得中のalarmは延期した。通常の利用者操作を停止するメンテナンス画面は導入していない。

復元検証が成功してから追加版のDB初期化を許可し、転送OFF・許可グループ空・転送queue空を実行中のDOから確認した。既存行を照合した後、診断機能を含まない通常bundleへ切り替え、実行中の一時経路が消えたことをHTTPで確認して一時Secretを削除。CFの有効版100%・設定・実module・公開画面200/未認証session401を最終照合した。

ローカルの追加保全試験では、空DBの非初期化、通常閲覧によるprocessing非変更、alarm延期、session復元、追加テーブルのみの変更、通常版への移行後の既存session有効性を確認した。転送版の既存全160件と型検査・Studio全181件・2-worker接続検証も成功済み。

本番で実パスワードを入力してログインする確認は利用者の端末側で行う。こちらから新しい認証試行やパスワード変更は行っていない。実LINE素材取得・転送・通知、許可グループ指定は未実施。転送をONにする前に、同一チャネル/許可グループ、通常runner・予算・無料枠、転送待ちを含むDO全体の復旧を確認する。今回の別DB復元検証はCloudflareの本番PITR復旧試験ではない。
