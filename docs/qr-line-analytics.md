# Analytics運営出席のイベント取り込み

既存Analyticsを読み取り調査し、`GET /api/operator/events` と実際の認証 `POST /api/operator/login` を利用するQR側アダプターを追加しました。Analyticsリポジトリは変更しません。

設定は実際のHTTPS originと運営パスワードをサーバー側secretで保持します。ログインで取得した8時間の運営Cookieは取り込み処理のメモリ内だけで使用し、ログ・ブラウザ・DBへ出しません。取り込みはAdminのみです。HTTPS固定・リダイレクト拒否・タイムアウト・本文256KiB・イベント100件までに制限します。

APIが提供する項目はID、タイトル、開催日時、チェックイン有効フラグ、チェックイン開始・終了です。カテゴリ（イベントの種類）、会場、定員はこのAPIにありません。そのためカテゴリを捏造せず、会場・定員は取り込み時に運営が指定します。チェックイン無効または受付時間未設定のイベントはスキップします。

既存 `source=analytics, external_id=AnalyticsイベントUUID` と一意制約を再利用して二重登録を防ぎます。再取り込みは既存イベントのローカル編集・参加者・受付履歴を上書きしません。Analytics側にイベント作成・参加実績更新・PV/CVR変更を行いません。

Analyticsの運営イベントAPIが本番で公開済みか、実際の認証情報が利用できるかは別途接続確認が必要です。既存のカテゴリまで取り込むには、Analytics側が認可済みのAPIでcategoryを返す仕様変更が必要です。未確認のAPIや認証は利用しません。
