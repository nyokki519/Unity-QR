## 現在の状態

QR側の実装・モックAPI・ローカルCloudflareランタイムでの検証対象です。実際のLINEチャネル情報はコードに含まれていません。本番接続・公式LINEからの実送信確認は設定後に行います。既存のスタッフ受付は未接続でも利用できます。

## LINE側の準備

1. LINE Official Account Managerで対象の公式アカウントを選択する。
2. 設定 → Messaging APIから有効化する。LINE Login用チャネルとは別なので取り違えない。
3. LINE Developers Consoleで対象のMessaging APIチャネルを開く。
4. Basic settingsのチャネルID・チャネルシークレット、Messaging APIのチャネルアクセストークンを確認・発行する。実際の情報だけを使う。
5. Macで `npm run cloud:line-setup` を実行し、3項目を非表示入力する。アクセストークンをBot情報APIで確認してから、Cloudflare secretsへ保存する。ファイルやGitへ書き込まない。
6. 以下をWebhook URLとして登録する。

   `https://unity-qr-free-79cc330c2434.kukki519.workers.dev/api/v2/line/webhook`

7. Webhookの利用を有効にし、検証する。再送も有効にできる。検証リクエストの空eventsに対応する。
8. 「参加希望」等の既存キーワード応答と二重返信しないよう確認する。既存の挨拶・応答メッセージは運用に応じて調整し、全体の応答を不用意に停止しない。

公式の設定説明：<https://developers.line.biz/ja/docs/messaging-api/getting-started/>。

設定後、管理画面の設定で「認証設定あり」を確認します。この表示はLINE実送信の成功を意味しません。運営本人のLINE・専用テストイベントで初回参加、再発行、QR受付まで確認してください。

## イベントを受付対象にする

管理画面 → 設定 → 公式LINE・自動受付 → 各イベントの「申込設定」。

- LINE申込を有効にし、申込開始・終了を指定する。
- 申込期間と当日のQR受付時間は別。申込終了はイベントの受付終了以前とする。
- 1件だけ受付中なら、そのイベント名・日時を案内して登録する。
- 複数ならQuick Replyで選択する。13件を超える同時候補は運営対応を案内する。
- 開催・受付終了済み、定員到達、無効な古い選択は登録しない。
- 定員はLINEの参加予定者登録時もDBトランザクション内で確認する。スタッフの当日登録は既存の運用を維持する。

## 参加者側

- **参加希望**：LINE表示名を取得し、初参加なら登録。取得できなければ15分以内に名前入力を依頼する。複数イベント選択後に名前入力が必要になる場合がある。
- **QR / QR再発行 / 参加確認**：登録済みイベントの専用ページを案内する。イベントが複数なら選択する。
- **キャンセル**：対象イベントを明示した確認ボタンを返し、確定後に取消する。受付済みはスタッフへ問い合わせてもらう。
- 取消後の**参加希望**：申込期間・定員を確認して再登録する。

専用ページはLINE内ブラウザ・Safariで開けます。QRは当日の受付時間になってから発行し、約10分の短期有効期限で定期更新します。申込が数日前でも同じページが使えます。取消・受付済み・終了時は読み取り用QRを表示しません。リンク自体は受付終了の7日後に失効します。

リンクは本人用で、転送しないよう案内します。LINE本人のDMは署名で確認しますが、転送されたQRの提示者まで本人保証するものではありません。必要ならスタッフが参加者名を確認してください。LINE表示名は本名とは限りません。

## スタッフ受付

既存どおり、管理画面で対象イベントを選び、参加者が提示したQRをスキャンします。受付完了はサーバー確認後のみ表示し、二重受付は人数を増やしません。手動受付・名前検索・Adminによる取消も維持します。参加者一覧にLINE連携と来場回数を表示します。

リッチメニューは公式LINEへの「参加希望」「QR再発行」のメッセージアクションにすると手入力を減らせます。一般参加者へ運営管理画面を配布しないでください。

## 返信失敗・中断

管理画面 → 設定 → 最近のLINE処理で確認します。

- 返信済み：Reply APIが成功応答した。
- 失敗：登録エラー・LINEの非成功応答・中断など。エラーコードを表示する。
- 結果不明：APIタイムアウト等で送信済みか断定できない。
- 処理中：受付済みWebhookを処理している。

Webhook IDをDBに永続化し、再送で再登録・再返信しません。最大20件のバッチを同時処理し、プロフィール3秒・返信5秒の上限でバックグラウンド処理の長時間化を防ぎます。署名検証・永続受付後にCloudflare応答を返します。ただしサーバー中断時に外部送信まで必ず完了する保証はありません。起動時に残ったprocessingを中断失敗として記録します。結果不明は勝手に再送せず、参加者に「QR再発行」、未登録なら「参加希望」を新しく送ってもらいます。有料枠を使うPush APIへの切替はありません。

## 個人情報・バックアップ・復元

LINEユーザーIDはチャネルIDを含めてHMAC化し、参加者との対応だけを保存します。同名の既存参加者と自動結合しません。生ユーザーID・replyToken・認証情報はバックアップへ保存しません。QRページの秘密リンクはURLフラグメントで渡し、APIのAuthorizationへだけ送ります。DBにはリンクトークンのハッシュを保存します。

v3バックアップにはLINE対応・受付設定・リンクハッシュ・会話期限・処理状態を含みます。v2の旧バックアップも新コードで読めます。バックアップは個人情報を含むため、運営だけが安全な場所で保管してください。

Schema 3適用後の旧コードへの単純ロールバックはできません。旧コードは未対応バージョンを拒否します。問題時は受付を止め、互換性のある新コードで修正するか、バックアップ取得後の差分を確認して復元します。復元は**空の隔離DB**への既存importOwnedSnapshot経路で行い、稼働DBへ上書きしません。クラウドの既存DBを削除する自動復元コマンドは提供しません。

保存期間・削除依頼は運営の方針に合わせてください。このフェーズは参加者データを自動削除しません。LINE解除や参加者削除の要望はAdminが本人確認し、受付履歴への影響を確認して対応する運用です。専用のセルフ削除UIは未実装です。

## 無料枠

ユーザーからのメッセージへReply APIで応答し、Push・一斉送信・自動リマインドを行いません。Replyの通数扱い・API制限はLINE公式の最新料金仕様を運用前に確認してください：<https://developers.line.biz/ja/docs/messaging-api/pricing/>。

Cloudflareの無料枠にもリクエスト・CPU・SQL容量の上限があります。超過時の停止・失敗は起こり得ますが、スクリプトが有料プランを契約することはありません。無制限無料を保証しません。運営人数・イベント数が増えたらCloudflareとLINEの利用状況を確認してください。

## Analytics

別紙 `qr-line-analytics.md` を参照。`npm run cloud:line-setup -- --analytics` で実際のAnalytics URL・既存運営パスワードを登録できます。取込は管理画面で明示した会場・定員、プレビューの同じ内容を確定して行います。Analytics側のAPIが未デプロイなら、接続済みとは扱いません。

設定を終えたらMacのターミナルで `unset CLOUDFLARE_API_TOKEN` を実行してください。

## 専用コードなしのQR再取得
一度専用コードでLINE本人へ紐づけた申込は、「参加QR」「参加希望」のどちらでもQRリンクを再取得できます。対象が1イベントなら直接返信し、複数なら本人の申込イベントだけを選択肢に表示します。今後の未紐付けの新しい申込を、名前・計測IDで勝手に紐付けることはしません。新しい申込を初めて受け取る際は、申込完了画面からコード付きメッセージを送ってください。

フォーム連携が有効で未紐付けなら、初回の専用コード送信を案内します。キャンセル済み・終了した申込にQRを発行せず、短いコマンドだけで参加を復活させません。旧LINE直接申込でキャンセルした参加の再開は、表示されるイベント選択ボタンで明示確認してから行います。フォーム連携なしの既存新規LINE申込は維持します。Reply APIのみ使用し、Push配信は追加していません。
